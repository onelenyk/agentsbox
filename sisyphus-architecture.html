3. Core Modules — What Each File Does

📦 operations.py 363 lines

Single source of truth. Every card operation goes through here.

  • create_card_only() → backlog
  • create_and_run() → sync (CLI)
  • create_and_run_async() → bg (Web)
  • run_card() → run existing card
  • resume_card() → reset steps, re-run
  • cancel_card() → kill processes + DB

⚙️ pipeline.py 564 lines

DAG execution engine with parallel waves.

  • topological_sort() → BFS levels
  • Wave execution → asyncio.gather
  • Reviewer loop → max 3 retries
  • Setup tools → fetch_jira, etc.
  • Worktree isolation → per step
  • Cancel check → between waves

🚀 launcher.py 268 lines

Spawns opencode subprocess, captures output.

  • opencode run → non-interactive
  • --format json --auto → JSON stdout
  • stdin=stdout/stderr=PIPE
  • proc.communicate() → waits exit
  • result.json → BaseResult validation
  • analysis.md → saved as resource

💾 state.py 254 lines

SQLite CRUD — 4 tables.

  • cards — id, pipeline, status, platforms
  • runs — id, card_id, status, error
  • steps — id, run_id, agent, status
  • resources — run_id, step_id, filename

🔄 fsm.py 40 lines

State machine — validates transitions.

  • pending → running → completed/failed/timeout
  • error → running (retry allowed)
  • ⚠️ failed → running (BLOCKED — known issue)

🏃 runners.py 238 lines

AI runner CRUD — opencode, Claude, Ollama.

  • add_runner() → name, binary, model
  • health_check() → binary + API key + URL
  • get_default_runner() → auto-seeded
  • Web UI → /runners page

🛠 recovery.py 82 lines

Crash recovery on startup.

  • running steps → error (orchestrator_crash)
  • terminal runs → failed/completed
  • terminal cards → failed/completed

🌲 worktree.py 167 lines

Git worktree isolation per step.

  • init_bare_clone() → lightweight clone
  • create_worktree() → per-step branch
  • set_access() → read/analyze/edit
  • remove_worktree() → cleanup
